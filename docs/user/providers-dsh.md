# DeepSeek Harness — native Provider (development preview)

This fork adds a separate **native SDK/JSON-RPC** Provider named **DeepSeek Harness** (driver kind `dsh`). It is **not ACP**, does not replace Codex or Claude, and is **disabled by default**.

## Current implementation

- Package: `packages/provider-dsh`, with T3 server registration, browser/mobile client registry, model defaults and provider icon.
- Process: per-T3-session `@deepseek-ai/dsh-sdk-client@0.2.2-rc.1` launching the `sdk` profile; session home is isolated by instance and stable thread identity. DSH model route and ID are configured independently.
- Health: launches an SDK handshake in a separate probe home, without performing inference. A successful handshake is **not proof of authentication or of usable model inference**.
- Sessions: create, send text turns, restore the native session ID, publish terminal status. The native protocol has no per-session cancel/close/rewind/fork methods.
- Events: map completed assistant messages and native `tool/call`, `tool/result` events to T3 items. Native `turn/end` reason `completed` is the only successful outcome; cancelled, interrupted and failed turns are distinct.
- Human input: one-shot SDK tool approval and `user-question/ask` are presented as T3 runtime requests. Missing handlers, malformed replies and unsupported forms fail closed; "always allow" and "allow for session" are not enabled.
- Policy: **Supervised mode only** in the current adapter. No claims of T3 server-side sandbox enforcement; confirm all DSH tool permission paths during the independent security review.
- Unsupported T3 facilities do not claim native support: fork/rollback, active steering, stop, attachments, persistent background tasks, token-by-token streaming, complete subagent visualization and provider-owned text generation.

**Do not merge to main or use against production/important workspaces yet.** The test DSH child runs with the host OS identity. Environment filtering is not a filesystem or tenant sandbox; authenticated multi-user security has not been established. A passing unit test is not a live integration test. Full native parity with Codex is a *goal*, not a present capability.

Full live acceptance and security gates: [DSH native live acceptance](../verification/dsh-native-live-acceptance.md).

## Development commands

```bash
pnpm install --frozen-lockfile
pnpm --filter '@t3tools/provider-dsh' typecheck
pnpm --filter '@t3tools/provider-dsh' test
pnpm --filter '@t3tools/client-runtime' typecheck
pnpm --filter 't3' typecheck
```

T3 Code server must be able to launch the DSH SDK-matched runtime. The optional binary override is a built Node CLI entry-module path, **not** a shell executable. Configure the DSH route and model ID matching the installed DSH version; supply secrets through restricted Provider instance environment bindings.
